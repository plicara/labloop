# Follow-up audit of labloop 1.0.2

Scope: source, tests, release scripts, CI, package contents, and current user-facing documentation, starting from tag `v1.0.2` / commit `f367462`. Changes are on `bug/evidence-boundary`; the package version remains unchanged. No release, push, or publication was performed.

## Correctness and specification

The audit fixed the following cases. Portable behavioral regressions were reproduced with failing tests before implementation; Linux execution requires the separate verification noted below.

| Finding | Correction | Regression coverage |
| --- | --- | --- |
| Writable binds accepted arbitrary dedicated directories, including credential/configuration locations | Fixed evidence-root allowlist with canonical containment checks | `tests/test_sandbox.py`: outside-root, root, symlink redirects, accepted evidence path, CLI refusal |
| Sandbox self-check deleted preexisting fixed-name marker files | Exclusively owned temporary probe directories, validated before creation | `test_the_self_check_preserves_existing_files` |
| Rejected ledger edits survived Git revert and changed later incumbents | Restore the trusted pre-proposal ledger by atomic replacement before recording rejection | `test_rejected_ledger_tampering_cannot_change_the_next_incumbent` |
| Proposed code deferred protected-file or ledger edits until measurement, after the proposal-only check | Reuse integrity checks after completed ordinary, confirmation, baseline, and noise measurements before reading their metrics; restore detected ledger changes | `tests/test_measurement_integrity.py`: phase-specific rejection, unchanged incumbent, ledger overwrite/delete/symlink recovery, crash/timeout precedence, dirty-baseline preservation, benign artifacts, CLI rejection |
| Bubblewrap lacked explicit capability dropping and terminal-session detachment | Add `--cap-drop ALL` and `--new-session` to the existing wrapper | Argument assertions plus Linux-only capability and controlling-terminal checks |
| Timeout handling stopped at the shell while a child retained the output pipe | Kill the original POSIX process group and bound subsequent pipe draining; clean up on interruption too | `test_a_timeout_kills_a_child_even_after_the_shell_exits` and existing process-group tests |
| New proposal directories pulled later evaluation artifacts into kept commits | Enumerate untracked files individually before measurement | `test_a_new_directory_does_not_sweep_later_artifacts_into_the_commit` |
| A waiting peer's manifest could misattribute a later trial's label/spec | Refresh the active manifest inside each trial lock | `test_each_trial_uses_its_own_run_manifest_after_a_peer_manifest` |
| Sandbox CI could pass by skipping unavailable integrations | Mandatory real backend self-check before collection in sandbox CI and publishing | `--require-sandbox`; unavailable-backend gate verified locally, real integrations require Linux |
| Release preflight ignored untracked files, treated network failure as version availability, and mutated state during dry runs | Read-only remote checks, explicit HTTP status handling, full Git status, editable-source verification, no bytecode/changelog/Git writes in dry runs | `tests/test_publish.py`, using stubbed external services and Git |

An independent second review reran the ledger, process-timeout, and artifact-staging reproductions against the fixes and found those cases closed. This is targeted verification, not a claim of exhaustive adversarial coverage.

The subsequent sandbox-integrity audit identified the measurement-time gap above. Its persistent-tampering reproduction is now rejected, including confirmation and baseline paths. Noise calibration also executes the measurement command, so it now checks integrity under the ledger lock and discards all statistics on a violation. An older peer-direction fixture relied on writing the ledger from the measurement command; it now injects its stand-in peer result through the trusted reporting callback after the first trial is recorded. The next-trial incumbent assertion remains intact.

Release smoke tests now use a separate repository from their virtual environment and explicitly disable proposer isolation for functional packaging checks. Publishing requires an explicit final confirmation and its own mandatory Linux sandbox gate; the manual workflow-dispatch path is removed. Source archives include the release script required by their bundled tests.

The documentation sweep updates evidence migration, host-measurement execution, local-socket limitations, hosted-agent networking, output-format precedence, default versus waiting lock behavior, release flow, and roadmap status. It removes the unsupported `--sandbox-exec` claim and the stale Alpha classifier without inventing a new stability guarantee. The measurement follow-up documents rejection phases, baseline cleanup, noise locking, and snapshot limitations. ## Limitations and follow-up

- Linux kernel isolation is not verified on this macOS machine. The new integration tests cover host/Git writes, private network namespaces, detached children, capability dropping, terminal detachment, and evidence surviving keeps and reverts, but must pass the mandatory Linux job before shipping.
- The measurement command runs on the host and may load proposed code. For adversarial experiments, isolate the entire workload on a disposable, credential-free machine. Read access, local Unix sockets, and a shared kernel also remain outside a confidentiality guarantee.
- Post-command snapshots cannot detect a protected file or ledger modified and restored within the command, authenticate printed metrics, or detect in-memory monkey-patching. Interrupted commands do not reach post-command checks; inspect the tree and ledger before resuming. The [evaluation-isolation proposal](evaluation-isolation.md) is a design direction, not an implemented containment guarantee.
- Evidence is caller-granted writable space, not authenticated audit data. Do not put credentials there or execute its contents as trusted code. Concurrent host-side path replacement is not a defended threat model.
- Kept commits select proposal paths, not immutable pre-evaluation snapshots. Evaluator changes to the same paths can still enter the commit. Ignored artifacts persist by design.
- Individual unmatched `--protect` patterns alongside valid matches are not rejected. Matching digests establish matching watched files, not identical loaded dependencies or valid science.
- Full command output is buffered in memory; only the stored ledger tail is bounded. Very chatty commands can still exhaust memory.
- Waiting directions serialize trials. Multi-host concurrent writers and Windows process/locking behavior remain unverified.
- Release tests mock remote availability and publishing interfaces. They do not establish that a future tag, GitHub Release, or PyPI upload will succeed.
